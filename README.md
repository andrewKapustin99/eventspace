# EventSpace — светлый редакционный вариант главной

Готовый статический сайт: HTML, CSS, JavaScript и все изображения. Включены последние изменения — подробные подсказки в блоке «Что есть на площадке».

Для публикации не нужны Python, Node.js, npm и локальная сборка.

## Что изменилось в этом варианте

- Светлая главная с молочным фоном, оливковыми акцентами и спокойными границами.
- Новый первый экран: крупный заголовок слева, фотография и ссылка на площадку справа.
- Заголовки Cormorant Garamond и интерфейс Manrope с кириллицей. Файлы шрифтов и лицензии включены в `assets/fonts/`.
- Обновлены карточки, категории, подборки, журнал, секции кейсов и блок для владельцев на главной.
- Всё новое оформление находится в `editorial.css` и применяется только к главной странице.
- Все прежние функции и страницы сохранены, в том числе подсказки об оборудовании.

## Обновление уже опубликованного репозитория

1. Распакуйте архив и скопируйте всё его содержимое в свою папку репозитория `eventspace`, согласившись на замену файлов. `index.html` остаётся в корне.
2. Обязательно скопируйте новый файл `editorial.css` и папку `assets/fonts/`.
3. В PowerShell в папке репозитория выполните:

```powershell
git add .
git commit -m "Refresh EventSpace homepage design"
git push origin main
```

GitHub Pages продолжит использовать ранее выбранные `main` и `/ (root)`. Повторно настраивать Pages не требуется. После публикации обновите страницу сочетанием Ctrl+F5.

## Проверка этой версии

Синтаксис JavaScript, 33 маршрута, фильтры, избранное, сравнение, пустые состояния и подсказки прошли программную проверку. События и остальные функции за пределами разметки главной сохранены без изменений. Кириллические символы проверены во всех шести файлах шрифтов.

Визуальная проверка в браузере на 1440 / 768 / 390 px не выполнена: среда предпросмотра в этой сессии недоступна. Адаптивные правила предусмотрены в CSS.


## Публикация через интерфейс GitHub

1. Создайте репозиторий, например `eventspace`. Для размещения на бесплатном аккаунте используйте публичный репозиторий.
2. Распакуйте архив на своём компьютере.
3. В репозитории выберите **Add file → Upload files**.
4. Загрузите содержимое архива: `index.html`, `app.js`, `style.css`, папку `assets`, `.nojekyll` и документы. Важно: `index.html` должен лежать в корне репозитория, а не внутри дополнительной папки. ZIP-файл загружать вместо исходников не нужно.
5. Нажмите **Commit changes** и сохраните файлы в ветке `main`.
6. Откройте **Settings → Pages**.
7. В разделе **Build and deployment** выберите **Source → Deploy from a branch**.
8. Укажите ветку **main**, папку **/ (root)** и нажмите **Save**.
9. Дождитесь завершения публикации. Адрес сайта появится на странице **Settings → Pages**. Если репозиторий называется `eventspace`, обычный адрес будет иметь вид `https://ВАШ-ЛОГИН.github.io/eventspace/`.

Если скрытый файл `.nojekyll` не попал в загрузку, его можно создать через **Add file → Create new file** с именем `.nojekyll`. Он отключает обработку сайта Jekyll.

## Как обновить сайт

Замените нужные файлы в ветке `main` и сохраните изменения. GitHub Pages повторно опубликует выбранную ветку.

Все пути к стилям, скриптам и изображениям относительные. Поэтому сайт подходит и для адреса с именем репозитория, и для корневого сайта `username.github.io`. Переходы между страницами используют `#/...` и не требуют серверных правил переадресации.

## Структура

- `index.html` — главная точка входа, должна находиться в корне.
- `app.js` — страницы, данные и интерактивность.
- `style.css` — исходное оформление и адаптивные стили.
- `editorial.css` — оформление новой главной.
- `assets/fonts/` — шрифты с кириллицей и лицензии.
- `assets/` — все изображения.
- `.nojekyll` — публикация без Jekyll.
- `ASSETS.md` — сведения об иллюстрациях.

Это дизайн-прототип с вымышленными площадками и контактами. Формы имитируют отправку, избранное и сравнение хранятся в текущем браузере. Серверная часть не нужна и не входит в эту версию.
